Decisions:
- **Anything the client shouldn't act on decodes to `IgnoredMessage`, never an exception.** That covers unknown types, malformed JSON, non-object JSON, and known types with missing or wrongly typed fields. The server is authoritative, and one bad frame shouldn't end a session.
- **`ReceiveAsync` returns null for any end of connection.** A close frame, a `WebSocketException` (network drop) and an `ObjectDisposedException` all give null, so the session has one "connection ended" signal. Cancellation still throws.
- **`SendAsync` throws `TransportException` unless the socket is `Open`.** `ClientWebSocket` allows sends after the server's close frame (half-closed), but nothing answers them. The loopback test found this.
- **401 detection uses `ClientWebSocketOptions.CollectHttpResponseDetails` and `HttpStatusCode`.** A 401 comes back as an upgrade response before any socket exists, so this is the only way to tell it from a network failure. Any other connect failure is a plain `TransportException`.
- **Deviation from the task wording (2.2).** The task said "unit tests against a scripted fake" for send, receive and close. I tested the real `WebSocketTransport` against an in-process loopback server (`NotIrc.Tests/Transport/LoopbackServer.cs`, an `HttpListener` that returns 401 for a wrong token) instead. That exercises the actual code, which a test of a fake would not. The scripted fake `ITransport` and `ITransportFactory` for session tests is not built yet and belongs to §3, where it is first used.
- **Byte counting.** `MessageLimit` counts the exact string with no trimming, per design.md. The spec's "empty or whitespace-only is not sent" rule is a session and view-model concern for §3.5, not part of this function.

Gotchas:
- In the loopback test server, `WebSocket.Abort()` does not drop the TCP connection (the client hung until its 10s timeout). `Dispose()` does, so the abrupt-drop test uses that.
- Tests in `NotIrc.Tests` use `ThrowsAsync` with cancellation tokens and a 10s `Timeout` constant, so a hung loopback test fails slowly rather than hanging the gate.
- `ScaffoldTests` is deleted, because real tests now exist.
- Run gates unsandboxed. The loopback tests bind 127.0.0.1 ports.
