What landed in `NotIrc.App/`:
- `ViewModels/MainViewModel.cs`: wraps a `ChannelSession`. Takes `(session, serverAddress, Action<Action> post)`. `post` runs work on the UI thread in order (`Dispatcher.UIThread.Post` in the app, inline in plain tests). Exposes `Entries`, `Presence`, `StatusText`, `IsStatusOk/Busy/Bad`, `ErrorText`, `InputText`, `ByteCount`, `ByteCounterText`, `IsOverLimit`, `CanSend`, `ShowChooseNickname`, `SendCommand`, `ChooseNicknameCommand`.
- `ViewModels/EntryViewModel.cs` (log rows and notice wording), `NicknamePromptViewModel.cs`, `StartupErrorViewModel.cs`.
- `MainWindow.axaml(.cs)`: status bar, red banner for a rejected token, log (auto-scrolls), presence column on the right, input row with byte counter, "Too long" warning and Send button.
- `NicknamePromptWindow`: pre-filled with the rejected nickname; OK returns the trimmed nickname, Cancel and close return null. `StartupErrorWindow`: lists each settings error.
- `App.axaml.cs`: `SettingsLoader.Load(desktop.Args)`. Invalid gives `StartupErrorWindow` and never builds a session. Valid builds `ChannelSession` with `WebSocketTransportFactory`, starts it on the window's `Opened`, and disposes it (3s wait) on `desktop.Exit`. The prompt callback shows the dialog on the UI thread and answers null if the main window isn't visible.

Decisions and why:
- **Send button vs Enter.** Task 5.1 says disable sending when not joined, but `chat-messaging` says submitting while reconnecting shows a "not connected" notice and keeps the text. Both hold: the Send *button* is enabled only when joined, with non-empty text within the limit (`CanSend`). The Enter key runs `SendCommand`, which is allowed whenever there is non-empty text within the limit, so Enter while not joined gives the notice and keeps the text.
- **Rejected-message restore.** On a `MessageRejected` notice the input gets the last sent text back, but only if the input is empty (a newer draft is never overwritten).
- **Own-message styling** is decided when the entry arrives, from `Session.Nickname` at that moment, and stays fixed afterwards.
- **Token-rejected** shows both the status text "Disconnected: token rejected" and a red banner. No separate window.
- **`Dispatcher.UIThread.Post` method group** doesn't convert to `Action<Action>` (overloads), so the app passes a lambda.

Gotchas:
- **`Avalonia.Headless.XUnit` 12.0.4 doesn't work with the project's xunit.v3 4.0.2.** It is built against xunit.v3.extensibility.core 3.2.2, and `[AvaloniaFact]` fails discovery with `MissingMethodException … TestIntrospectionHelper…`. I did not change xunit versions. Instead `NotIrc.Tests/App/Ui.cs` uses Avalonia's xunit-agnostic `HeadlessUnitTestSession.GetOrStartForAssembly` and tests are plain `[Fact]` calling `Ui.Run`/`Ui.RunAsync`. `TestAppBuilder.cs` holds the `[assembly: AvaloniaTestApplication]`. design.md still mentions `Avalonia.Headless.XUnit`; the package is still referenced but unused by the attributes.
- The toolkit generates `OnStatusChanged(SessionStatus)` for a `Status` property, which collided with a handler of the same name; the session handlers are now `HandleSession…`.
- `-warnaserror` analyzers hit: CA1305 (use `CultureInfo.InvariantCulture`), CA1822, CA1826, CA1861; `TextBox.Watermark` is obsolete (`PlaceholderText`), error AVLN5001.

Self-review: checked `chat-messaging`, `channel-presence`, `channel-session` (status and prompt) and `client-configuration` against the app. Each scenario the UI owns has a test (22 new tests: 13 view-model, 9 window). The token never reaches the UI (`DisplayAddress` has no query).
