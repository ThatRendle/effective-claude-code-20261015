Public surface for §5:
- `var result = SettingsLoader.Load(args);` then if `!result.IsValid`, show `result.Errors` (one message per missing setting, each naming `--x`, `NOTIRC_X` and the `notirc.json` key) and do not connect.
- If valid, `new SessionOptions(result.Settings.ConnectionUrl, result.Settings.Nickname)`.
- Show `Settings.DisplayAddress` in the UI, never `ConnectionUrl`.

Decisions and why:
- **Environment is read by hand, not with the `EnvironmentVariables` provider.** The loader takes an `IDictionary` (default: the process environment), strips `NOTIRC_` and feeds an in-memory source. That lets tests pass an environment without touching the process.
- **Provider order** is file, then environment, then command line, so the command line wins, as the spec says.
- **Blank values count as missing** (whitespace-only is trimmed to null).
- **All missing settings are reported together**, not just the first one.
- **Server address:** a value containing `://` is parsed as given, and anything else gets `wss://` in front. Only `ws` and `wss` are accepted. The path is always `/ws`, so a trailing slash or other path is dropped. The default port is omitted from the URL. An invalid address gives one error ("The server address is not valid…"), and none of the error text contains the token.
- **A malformed `notirc.json` becomes an error result**, not an exception. The file is looked up in the working directory unless a path is given.
- **The token is URL-escaped** with `Uri.EscapeDataString`.
- **The "settings file ignored by version control" scenario** is a test that reads `.gitignore` and looks for the line `notirc.json`.

Self-review: every `client-configuration` scenario has a test (file only, argument over file, environment over file, token missing, token not shown, ignored file, local server). `ConnectionUrl.ToString()` does contain the token. That is deliberate, since the transport needs it, and §5 must not bind it to anything.
